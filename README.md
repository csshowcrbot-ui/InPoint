## 🌟 系統核心亮點

- **日系簡約極致美學**：以森林青綠 (`#1A5E42`)、和紙白 (`#F4F7F5`) 與尊榮香檳金 (`#C89B3C`) 為基底，打造高質感視覺品牌體驗。
- **日系極致視覺現場大抽獎 (Live Lottery)**：大螢幕專屬和風舞台，內建「和紙米白」與「侘寂玄墨」雙主題切換、鳥居緋紅與香檳啞金點綴，支援 100% 現場已報到名單連動、多名額批次抽取與防重複中獎機制。
- **雙軌無縫自動平滑滾動得獎榜**：得獎名冊採用雙軌鏡像循環算法與亞像素平滑推進，支援滑鼠懸停暫停與手動滾輪瀏覽，大螢幕長時間輪播不卡頓、不跳格。
- **現場新增貴賓雙軌操作**：現場臨時到場或補登記時，可自由選擇 **「確認新增（未報到）」** 或 **「✓ 完成報到（直接簽到）」**，自動記錄報到時間與經辦標記，尊榮貴賓自動播放迎賓音效。
- **60 秒動態防作弊 QR Code**：採用 TOTP 時間窗口安全算法，大螢幕條碼每 60 秒自動刷新並平滑倒數，前次條碼立即過期，徹底防止遠端截圖代簽。
- **無狀態 Session 自動復原**：專為雲端 Docker 容器（如 Railway）重新部署設計，即使伺服器重啟或容器更新，記憶體重置也不會發生 401 登入失效中斷。
- **全新資料庫自動熱遷移 (Live Migration)**：首次連接全新 PostgreSQL 資料庫時，自動自舊資料庫完整同步歷史活動、名冊與會員資料，無痛平移。
- **快速連續報到流水線**：報到櫃檯搜尋欄位具備薄荷綠高對比辨識，輸入員工卡號/姓名後按下 `Enter` 鍵立即一鍵報到，並自動清空欄位保持焦點，支援秒級連續作業。
- **卡號前導 0 自動忽略**：系統自動相容開頭含 `0` 的員工卡號（如輸入 `00601441` 與名冊 `601441` 均能 100% 精準匹配）。
- **主持人唱名確認與提詞聯動**：看板中每位到場貴賓具備專屬「📢 點擊唱名」按鈕，點擊後轉為「✓ 已唱名」，開場致詞提詞單即時連動。
- **Excel「桌號 / 組別」一鍵匯入**：名冊匯入自動對應桌號/組別，同仁手機掃碼簽到成功後立即顯示所屬用餐席位或小組（如 `VIP-1 主桌`、`第十三組`）。
- **全平台適配與快取自動破除**：全面適配電腦螢幕、平板（iPad）、手機以及大螢幕投影；內建版本戳記機制，避免瀏覽器載入舊快取。

## 🛠️ 系統架構與技術棧

### 後端技術 (Backend)
- **平台核心**：.NET 8.0 (C#) Minimal APIs
- **資料庫引擎**：Entity Framework Core 8.0 雙軌支援：
  - **正式環境**：Railway 雲端平台 PostgreSQL（內部私有高速專網）
  - **企業內網**：Microsoft SQL Server 2016+
- **即時通訊**：ASP.NET Core SignalR（多端秒級狀態同步廣播）
- **安全算法**：HMAC-SHA256 TOTP-like 60 秒短效 Token 窗口驗證
- **Session 機制**：Token-based 附帶無狀態資料庫自我還原

### 前端技術 (Frontend)
- **架構設計**：原生 HTML5 + Vanilla CSS3 + ES6+ 模組化設計（Single Source of Truth, SSOT）
- **QR Code 引擎**：內建標準 ISO/IEC 18004 QR Code 編碼庫（支援所有手機相機與 LINE 原生解碼）
- **即時匯流排**：BroadcastChannel + SignalR 跨分頁與跨裝置無延遲同步
- **音效合成引擎**：Web Audio API 原生音效合成器（無需外部音效檔案即可播放雙音階簽到鈴聲與 VIP 號角）
- **Excel 解析器**：SheetJS (XLSX) 高相容性前端試算表解析

## 📱 功能模組與介面說明

### 1. 報到處作業端 (Staff Check-in)
> 路徑：`index.html` ➜ 【📱 報到處作業端】

- **即時模糊檢索**：支援依「員工卡號」、「員工編號」、「貴賓姓名」、「所屬單位」或「手機號碼」即時篩選。
- **極速一鍵報到**：
  - 搜尋欄位採用薄荷綠高對比底色，聚焦時散發微光提示。
  - 輸入卡號後直接按下鍵盤 **`Enter`**，系統即刻完成簽到並播放成功音效。
  - 報到成功後搜尋欄位**自動清空並自動全選保留游標焦點**，櫃檯人員無需滑鼠操作即可連續刷卡報到。
- **撤銷確認防呆**：已報到人員若需取消簽到，具備二次確認對話框，避免誤觸。
- **姓名遮蔽保護**：工具列提供「🔒 姓名遮蔽：開啟/關閉」切換開關，符合個資規範保護隱私。

### 2. 現場單筆新增貴賓 (可選完成報到 / 確認新增)
> 路徑：`index.html` ➜ 工具列點擊【➕ 現場新增貴賓】

- **彈性雙軌報到狀態選擇**：
  - ⚪ **僅新增名冊 (未報到)**：預設建立貴賓名冊資料，供後續現場簽到。
  - 🟢 **現場已到場 (直接完成報到)**：專為現場臨時抵達之貴賓設計，建檔同時即刻標記為已報到。
- **獨立操作按鈕**：
  - **【取消】**：關閉對話框並重置表單。
  - **【確認新增】**：以未報到狀態建立貴賓（Toast 提示「貴賓已新增」）。
  - **【✓ 完成報到】**：以已報到狀態建立貴賓，自動記錄報到時間與經手人標記，並播放成功簽到音效。
- **防重複與防連點保護**：
  - 自動偵測自訂編號是否重複，若重複即刻提供防呆警示。
  - 送出期間按鈕自動禁用，防範重複連按。

## 💾 資料庫架構與存放位置

### 1. 資料庫連線配置 (`appsettings.json`)

目前系統正式環境已全面遷移至 **Railway 平台之專用 PostgreSQL 資料庫**：

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "postgresql://postgres:iuPBfhRMHqoceSvHBuRPwlezdwgeucap@postgres.railway.internal:5432/railway"
  }
}
```
> **環境相容性機制**：
> - **Railway 線上容器**：透過內部專網網域 `postgres.railway.internal:5432` 高速安全連線。
> - **本機開發端**：內建自動偵測，若本機無法解析內部專網網域名稱時，會自動切換備援連線，開發測試不受影響。

### 2. 資料表結構 (Schema)

#### 1. 活動場次表 (`checkInEvents`)
- `EventId` (VARCHAR(100), PK)：活動場次代碼
- `EventName` (VARCHAR(255))：活動名稱
- `EventDate` (TIMESTAMP)：活動日期時間
- `Location` (VARCHAR(255))：活動地點
- `Description` (VARCHAR(1000))：活動備註說明

## 🚀 雲端與主機部署指引 (Railway / Docker / IIS)

### 方案 A：Railway 平台一鍵雲端部署 (建議)
1. 將程式碼推送到 GitHub 儲存庫 `main` 分支。
2. Railway 專案綁定 GitHub 儲存庫後，平台會依據專案配置自動觸發 Docker Build 與啟動。
3. 容器首次啟動時，會自動檢查資料庫結構並觸發**自動熱遷移 (Live Migration)**，無縫轉移所有活動與貴賓名單。

### 方案 B：Windows IIS 主機發布
1. 在開發目錄下執行發布腳本：
   ```powershell
   .\publish.ps1
   ```
2. 將 `publish\` 資料夾內的所有檔案複製並覆蓋至 IIS 網站實體目錄。
3. 瀏覽器開啟網站首頁並按下 **`Ctrl + F5`** 清除舊快取即可開始使用。

## ❓ 常見問題與維護指南

### Q1：現場新增貴賓時，若只建檔不想立即報到該如何操作？
在新增貴賓彈跳視窗中，點擊 **【確認新增】** 按鈕（或保留上方選取的「僅新增名冊 (未報到)」），系統即僅建立名冊而不執行簽到；若貴賓已到現場，請直接點擊綠色 **【✓ 完成報到】** 按鈕。

### Q2：若伺服器重新部署或重啟，正在使用的操作會被強制登出嗎？
**不會**。系統已內建無狀態 Session 自動復原機制，即使後端容器重新發布重啟，伺服器在接收到請求時會自動自資料庫恢復會員授權，絕不影響現場報到作業。

### Q3：大螢幕動態 QR 碼可以離線運作嗎？
**可以**。系統前端內建標準 UTC 60 秒時間窗口算法與純 JavaScript QR Code 生成器，即使伺服器連線短暫不穩定，大螢幕仍能持續生成 60 秒動態 QR Code 與平滑倒數計時。

### Q4：員工卡號前面有 `0`（例如 `00601441`）如何處理？
系統後端與前端已全面內建智慧過濾器，自動去除前導零進行雙向比對。無論名冊輸入 `601441`、刷卡機讀出 `00601441` 或手機輸入 `00601441`，系統皆能 100% 精準匹配成功。

### Q5：建立新活動與刪除活動時的管理授權密碼為何？
為了防止非授權人員隨意新增、覆蓋或誤刪活動場次與所有貴賓名單，建立新活動與在管理中心刪除活動場次時，系統強制要求輸入管理授權密碼：`ZiEiHrpPq@`。
